# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Gemini CLI, Cursor and others) when working with code in this repository. `CLAUDE.md` only imports it (`@AGENTS.md`): edit this file, not that one.

## Commands

- `make task`: run before committing. generate → tidy → lint-fix → fmt → ci; it edits files. `make ci` is read-only (mod-check, fmt-check, lint, lint-profiles, openapi-lint, openapi-breaking, cover: the order of its prerequisites in the Makefile) and runs the checks of GitHub CI's lint and test jobs. Keep `ci` read-only: anything that fixes belongs in `task`. Workflow targets chain their steps as prerequisites, run left to right (`.NOTPARALLEL` keeps the order under `make -j`); never call `$(MAKE)` from a recipe.
- `make test`: all tests with `-race`, through gotestsum (`GOTESTSUM_FORMAT=testname|dots|github-actions`, default `pkgname`). Single test: `gotestsum -- -race -run '^TestAPI$/should_reject_POST' ./internal/api/` (plain `go test` works too).
- Tools are developer-installed binaries, never `tool` directives in `go.mod` (offline use, clean caches, a lean `go.mod`): golangci-lint, mockery, gotestsum, benchstat, vacuum, oasdiff, gocover-cobertura. Versions are pinned in the Makefile (`*_VERSION`, golangci-lint's kept in sync with `ci.yml`); `make install-tools [TOOLS=…]` `go install`s all but golangci-lint. CI installs them through the composite action `.github/actions/install-tools` (`with: tools: …`), which caches the built binaries keyed on each tool's `*_VERSION` and the Go version, so a tool compiles only when its version changes; never call `make install-tools` directly in a workflow. Each target depends on `check-<tool>` for the tools it runs (`scripts/check-tool.sh`: missing → error with the install command; other version, read with `go version -m` → warning); `make check-tools` checks all. To add a tool: `*_MOD`/`*_PKG`/`*_VERSION` variables, a `check-<tool>` target, an `install-tools` line, and the tool in the `install-tools` step of the CI jobs that use it (and in `GO_TOOLS` of the `.gitlab-ci.yml` jobs).
- GitLab CI: `.gitlab-ci.yml` mirrors `ci.yml` for projects hosted on GitLab (this repository never runs it). Every job script is a make target; a check added to one CI goes in the other too. Versions outside the Makefile (Go, golangci-lint, hurl, Docker) are its top-level variables, kept in sync with `ci.yml`. `make cover-cobertura` (gocover-cobertura) writes the Cobertura report for merge requests. Validate with GitLab's CI Lint or `gitlab-ci-local --privileged`.
- Lite kit: `make export-lite DEST= MODULE= NAME= [FORCE=1]` (`scripts/export-lite.sh`) copies a smaller, renamed copy of the template into another directory: the shared files listed in the script, then `_kit/` on top (the kit's own Makefile, `AGENTS.md`, CI files, lean `.gitignore`/`.dockerignore`, and `internal/api` tests with a hand-written fake instead of mocks), and `.golangci.lite.yml` as `.golangci.yml`. `_kit/` starts with an underscore so `go ./...` skips it: its Go files are built and linted only in an export. The `lite-kit` CI job (both CIs) exports it and runs its `make ci`. When changing a shared file, the API's test cases or the golangci-lint version, update `_kit/` too (its handler tests mirror `internal/api/handler_test.go`; its Makefile and CI files pin golangci-lint).
- `make lint`: `go vet` + golangci-lint linters. `make fmt` rewrites files (gofumpt + gci); `make fmt-check` only reports and is what CI runs.
- Lint profiles: `LINT_PROFILE ?= full` (`.golangci.yml`, what CI runs) or `lite` (`.golangci.lite.yml`, correctness only); every lint/format target passes `--config $(LINT_CONFIG)`. Lite must stay a subset of full: `make lint-profiles` (in `make ci`; `scripts/lint-profiles.sh`) compares the enabled linters and formatters and runs lite. Settings and exclusions of the linters lite keeps are copied from full: change them in both files.
- Lint policy (`.golangci.yml`, grouped by purpose): lines up to 120 characters (`lll`), no magic numbers (`mnd`: name them as constants), sentinel errors wrapped with `%w` (`err113`, `wrapcheck`), blank-line rules (`wsl_v5`, `nlreturn`; `make lint-fix` applies them), every test parallel (`paralleltest`), requests built with a context (`noctx`: `httptest.NewRequestWithContext(t.Context(), ...)`). `funlen`, `goconst`, `gocyclo`, `err113`, `wrapcheck` and `errcheck` skip `_test.go`. A `//nolint` names the linter and gives a reason (`nolintlint`).
- OpenAPI: `api/openapi.yaml` (3.0.3, hand-written) is the contract clients generate code from: change it in the same PR as the handler. `make openapi-lint` (vacuum, ruleset `api/vacuum.yaml`, warnings fail; switch a rule off there with a reason, never otherwise) runs in `make ci`. The contract test (`internal/api/openapi_test.go`, kin-openapi, test-only: never import it outside `_test.go`) requires the routes registered through `a.handle` (always use it, never `a.mux.HandleFunc`) and the spec's operations to be the same set; validates every handler/component test response (`IncludeResponseStatus: true`; `/foo/` never matches `/foo`); and requires every documented response to be produced by a case in `TestOpenAPI_responses_match_spec` (add one with each new response). 404/405 and HEAD stay undescribed. `info.title` and the contact URL hold the project name (`make rename` sets them); `info.version` is the last release, bumped in the release PR. `make openapi-breaking` (`scripts/openapi-breaking.sh`, oasdiff, in `make ci`; the CI lint job checks out full history for the tags) fails on changes that break clients of the highest final `vX.Y.Z` tag (`--print-base` shows it; a tag without the spec skips): prefer additive changes or a new `/v2/...` path next to a `deprecated` old one; a deliberate break gets a line in `api/oasdiff-ignore.txt` in the same PR. Never paste a real oasdiff message into a comment there: oasdiff matches comment lines too.
- Test layers: unit (`handler_test.go`, mocked `Fooer`), component (`component_test.go`, real `Fooer`, in-process HTTP; not "integration"), integration (`//go:build integration`, `TestIntegration_*`, external dependencies such as Docker containers; `make test-integration`, never run by `make test`; `.golangci.yml` lints the tag), functional (hurl, `make test-functional`).
- `make test-functional`: builds `bin/<NAME>`, starts it on a free port (`-port=0`, the bound address is read from the `"msg":"listening"` JSON log line), runs `test/hurl/*.hurl`, stops it. `bash scripts/hurl.sh <base-url>` targets a running server. Recipes and docs run scripts with `bash scripts/…`: a gonew copy (a module zip) has no executable bits.
- `make cover`: coverage without `mocks/` (filtered in `COVER_PKGS`; CI runs `make cover COVERPROFILE=coverage.txt`, and `codecov.yml` ignores the mocks too).
- `make bench` (`BENCH=` filter, `BENCH_COUNT=6`): `-benchmem` runs saved raw in `bench.out`, then summarised by `benchstat` on stdout; `make bench-profile` writes cpu/mem profiles for `BENCH_PKG`. `make bench-compare BASE=<ref>` benchmarks the ref in a temporary git worktree and the working tree, then `benchstat` compares them (`scripts/bench-compare.sh`). Benchmarks are for people to read: there is deliberately no automated performance or allocation assertion, and neither `make task`, `make ci` nor GitHub CI runs them (`go test` still compiles them).
- `make mocks`: regenerate `mocks/` with mockery (configured in `.mockery.yaml`). Layout: `mocks/<package path>/<interface_snake>.go`, package `<pkg>mock`, type named like the interface (e.g. `foomock.NewFooer(t)` from `mocks/github.com/peczenyj/foo/foo`; an `/internal/` path element is dropped, since Go would not let other packages import the mock). To mock a new interface, add it under `packages:` in `.mockery.yaml`. Run it after changing `foo.Fooer`; CI fails on stale mocks. Never hand-edit the mocks.
- `make vendor`: tidy + vendor + verify. `vendor/` is git-ignored and must never be committed; while it exists locally, Go builds from it.
- `make build-debug`: `bin/<NAME>-debug` keeps DWARF and the symbol table, with `-N -l` (no optimizations or inlining) and no `-trimpath`, for `dlv exec bin/<NAME>-debug`. `make build` is the stripped release binary.
- `make run ARGS="-log-level=debug -log-format=json"`, `make docker`.

## Architecture

`cmd/server/main.go` `run()` → `internal/config.Parse` (flags, with `FOO_*` env vars as defaults, `envPrefix` + setting; flag > env > default; every invalid value reported, exit 2; a Kubernetes service link, `tcp://…` in `FOO_PORT`/`FOO_ADMIN_PORT`, is ignored with a warning) → `cfg.NewLogger` (slog text/json) → `api.New(foo.New(), logger, api.WithRecorder(metrics.Expvar()))` → `serveAll`: binds the public address and, when `cfg.AdminEnabled` (a field Parse sets from `-admin-port`, off by default: `-1`; the zero `Config` keeps it off), the admin address (`-admin-host`, `127.0.0.1` by default) before serving either, so nothing serves if one cannot listen; then `serve` logs `"listening"` with the bound address (graceful shutdown on SIGINT/SIGTERM or ctx cancel), and the admin server (`newAdminServer`, `admin.New()`) logs `"admin listening"`, with the public timeouts (pprof extends its own write deadline by `seconds`); its in-flight requests are cancelled when shutdown starts, so a running profile ends early instead of holding the shutdown: never do that on the public server, whose requests must drain; if either fails, the other shuts down too. Never put an attribute between `msg` and `addr` on the `"listening"` line: `scripts/hurl.sh` parses it.

- `internal/foo`: the `Fooer` interface (`Foo(ctx) (string, error)`) and the real implementation `*Bar`, built with `foo.New()` (pointer receiver; a real implementation's dependencies become `New`'s parameters).
- `internal/metrics`: the `Recorder` interface (`ObserveRequest(route, status, duration)`), `Nop`, and the expvar one: `metrics.Expvar()` returns it as a `Recorder` (its type is unexported, so no nil or zero one can reach `api.WithRecorder`) and is the process-wide one (`sync.OnceValue`: `expvar.Publish` panics on a name published twice, so never publish per instance; tests use unpublished maps). The route label is the ServeMux pattern or `metrics.Unmatched`, never the raw path (unbounded). A Prometheus `/metrics` would be a second `Recorder` (each `api.WithRecorder` adds one; expvar keeps recording) plus an `admin.Handle` route; it is a separate decision, not part of this code.
- `internal/admin`: the admin `http.Handler` on its own mux: `GET /debug/vars` (expvar) and `/debug/pprof/*`; `Handle` registers more routes. Never register on `http.DefaultServeMux` and never serve it.
- `internal/api`: the `http.Handler`. `ServeHTTP` caps the request body at `maxRequestBodyBytes` (with net/http's own writer: `http.MaxBytesReader` closes the connection only with that one), routes, then records the request (route pattern from `r.Pattern`, status through `statusWriter`) with every recorder given by `WithRecorder` (none by default), from a `defer`: a panicking handler is recorded as 500. `statusWriter` implements `http.Flusher`, `http.Hijacker` (recorded as 101) and `io.ReaderFrom` itself and unwraps for `http.ResponseController`; a superfluous `WriteHeader` is dropped and logged with its caller. `GET /foo` answers JSON (`MessageBody`). Handler errors are RFC 9457 problem details (`application/problem+json`, `api.Problem`, `writeError` → `writeProblem`): `problemFor` (`problem.go`) is the single mapping from domain errors to statuses (`errors.As`/`errors.Is`): `*foo.InputError` → 400 with its `Detail` field as `detail` (never `err.Error()`: wrappers up the chain may add internal context, which goes to the debug log only); anything else → 500 with a generic `detail`, the error logged at error level, never echoed. Domain errors go through `a.writeError(w, err)`; a handler validating its own request input answers `a.writeProblem(w, http.StatusBadRequest, "<client-safe text>")`. Add a status by adding a typed error (or sentinel) and a case in `problemFor`; never call `http.Error` in a handler. 404/405 come from `http.ServeMux` defaults and stay plain text (there is deliberately no catch-all route).

## Conventions

- Branches: `devel` is the default branch and the target of feature PRs; `main` is release-only and protected (PRs from `devel`, CI must pass). Never push to `main` directly. Releases: the CHANGELOG rename and the `info.version` bump in `api/openapi.yaml` go to `devel` together (`bash scripts/openapi-version.sh vX.Y.Z` checks it; CI checks it on tag pushes, ignoring a prerelease suffix), `devel` → `main` is merged with a merge commit (never squash), the tag `vX.Y.Z` is cut on that merge commit, and publishing its GitHub Release runs `.github/workflows/release.yml` (a `resolve` job, which also checks `info.version` so a wrong one stops everything, then `image` and `spec`), which attaches `api/openapi.yaml` to the release and pushes `ghcr.io/peczenyj/foo:vX.Y.Z` (+ `latest`) for linux/amd64 and linux/arm64 (manual runs republish an existing tag). The Dockerfile cross-compiles (`--platform=$BUILDPLATFORM`, `TARGETOS`/`TARGETARCH`): keep the runtime stage free of `RUN`, so arm64 builds need no emulation.
- Tests use testify (`require` when the test can't continue, `assert` otherwise), call `t.Parallel()`, and never bind fixed ports.
- Secrets: environment-only settings held in `config.Secret` (never a flag, never a plain `string`), read in `readEnv` with `readSecret(getenv, EnvX, required, &c.X)`, from `FOO_X` or from the file `FOO_X_FILE` names (read once, at most 64 KiB; both set, an unreadable or too-large file → usage error even for an optional secret; permissions left to the orchestrator; trailing `\r\n` dropped, other spaces kept; errors name the variable and path, never the value); a missing required one is an `ErrInvalid` usage error (wrapping `errSecretRequired`), except with `-version` (`Parse` drops those errors through `ignoreMissingSecrets`, so `<image> -version` needs no secrets; `readEnv` returns its errors as a slice for that). `Secret` prints/logs/encodes as `REDACTED`, or `(unset)` without a value (`Format`, `String`, `GoString`, `LogValue`, `MarshalText`; the value sits behind an unexported pointer); call `Reveal()` only where the value is sent. Never put a secret's value in an error or a log. foo itself declares none (README "Secrets" shows the three lines to add one).
- Logging: `logger.Error(...)`, not `ErrorContext(ctx, ...)`: nothing reads values from the context, and a cancelled request context must never look like it could affect logging. The global `slog` logger is acceptable too. `sloglint` is configured accordingly (`context: ""`, `no-global: ""`).
- Imports are grouped std / third-party / this module (gci `localmodule`, read from `go.mod`); `make fmt` fixes them.
- One project name: `NAME ?= foo` in the Makefile and the module path in `go.mod` (`MODULE`, read with awk) drive the binary paths (`bin/$(NAME)`), the image tag and labels (`NAME`/`SOURCE` build args), and the coverage filter. Scripts get values from make (`BIN` is exported to recipes; `make print-<VAR>` prints one). Workflows use `${{ github.repository }}` or `make print-NAME`. In Go, the name lives only in `programName` (`cmd/server`) and `envPrefix` (`internal/config`; tests use the `config.Env*` constants). Both lint configs carry gofumpt's `module-path`, empty unless the module has no dot in its first element. Never write the name or the module path anywhere else: the README "Adapting the template" section lists every place that holds them, and `make rename MODULE=… NAME=…` (`scripts/rename.sh`: portable awk, idempotent, works without git) rewrites exactly those, then runs `generate tidy` as prerequisites. A new place that holds the name must be added to both.
- `CHANGELOG.md` is newest first: `## [Unreleased]` is the first section, new bullets go at the top of it, then the releases from newest to oldest. At release, rename `[Unreleased]` to `[X.Y.Z] - date` and open a new, empty `[Unreleased]` above it; released sections are never edited. `.gitattributes` sets `merge=union` on it, which resolves local merges and rebases; GitHub ignores it, so a CHANGELOG conflict on a PR is resolved by keeping both bullets, newest first.
- `docs/superpowers/` (design specs, plans) and hidden `.*.md` notes are git-ignored: local working docs, never committed.
